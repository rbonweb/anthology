- Fix: when your PATH held a relative or empty entry (`.`, `::`, a leading or trailing `:`, or a folder such as `bin`), the repository you opened could take over the guard. Claude Code looked up the hooks' `sh` on that PATH, so a planted `./sh` could replace the guard and allow every tool call. The guard's installer could also run a planted `curl`, `tar` or `shasum`. The hooks now start with `/bin/sh`, and they drop those PATH entries for their own helpers, keeping the absolute ones in order and falling back to the standard system folders when none is left. The guard binary still gets your PATH unchanged. The sha256 check and the fail-closed behaviour are unchanged.
