- Fix: `Bash(atl *)` no longer approves `atl bypass <cmd>`, which runs any command unfiltered. ATL's hook now judges a typed `atl bypass <cmd>` (and its old name `atl proxy`) as `<cmd>` itself: your deny, ask and `Read()` rules apply to `<cmd>`, and the hook asks unless `anthology perm classify` shows `<cmd>` read-only, so `atl bypass git log -5` still runs without a prompt and `atl bypass rm -rf x` asks. It sees `atl bypass` as the bare word, behind a path to atl, `env` or an assignment, and inside `&&`, `||`, `;`, pipes, groups, `sh -c`, `xargs` and `find -exec`; only the plain spelling (the bare word `atl` at the start of a command, an unquoted command after it) is proven read-only, every other spelling asks. In auto mode nothing is rewritten, so the ask is about the line as typed. The ask holds with no deny or ask rule anywhere, and an ATL installed without the plugin has no classifier, so every `atl bypass` asks there. Other `atl` forms that run a command (`atl run`, `atl err`, `atl test`, `atl summary`, `atl <program>`) are not changed. This is ATL `1.2.1-anthology.9`; SECURITY.md and docs/atl.md no longer call the `atl bypass` approval an accepted risk.
