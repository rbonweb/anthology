Security review of PR 259 (atl/src/hooks/user_allow.rs, anthology_gate.rs atl_use/without_atl, read_only_proof.rs refine), probed with atl and anthology release builds in the pinned rust image, through plugins/anthology/bin/atl-hook with a symlinked anthology sibling.
Round 1 (3fc1f757): expansion-built subcommand words and the no-rule config were open. Round 2 (87999bea): about 100 typed-atl spellings ask with no settings, with only Bash(atl *), and beside deny/ask/Read rules; only the zsh dash precommand (- atl bypass ...) gets no decision, which Bash(atl *) does not match. Plain dangerous lines get no rewrite. The read-only proof for typed runners holds (atl bypass git log -5 passes; -C /tmp, --output, -c core.pager, ls /home, tree -o, redirects ask). Unreadable or invalid settings (a directory in place of the file, bad JSON) and managed-settings.json or managed-settings.d with allowManagedPermissionRulesOnly fail closed. Deny and ask beat allow across user, project and managed.
Found: (1) user_allow::matches treats Bash(find *) as covering find . -delete/-exec/-fprint and Bash(watch *) as covering watch cmd, but Claude Code never lets a prefix rule approve find actions or exec wrappers (watch, setsid, ionice, flock); the plain line gets permissionDecision allow and atl find . -delete / atl bypass find . -delete get no ask. (2) Allow rules come from the first .claude up from the hook process cwd (find_project_root); Claude Code loads project settings only from the primary dir, with no parent fallback. With no .claude in the project and Bash(*) in a parent .claude/settings.json, atl run sh -c ... gets no ask. Claude Code 2.1.326 spawns hooks in the project config root (qo()), not the Bash tool cwd, so a nested .claude reached by cd is not a live path. (3) AllowRewrite stays an explicit allow, which beats an MDM or server-managed allowManagedPermissionRulesOnly that atl cannot see. (4) A user rule written for an atl wrapped tool (Bash(atl git push:*)) never counts, because without_atl strips atl first; this is stricter, not a hole.
Why: the next round must model the Claude Code exceptions in user_allow and limit allow sources to CLAUDE_PROJECT_DIR, user and managed settings.
How to apply: re-run the find/watch prefix-rule probes and the ancestor .claude Bash(*) probe; the classifier proves only git, ls, find and tree in the container (tools absent), so wrapped-tool argv drift (atl npm X runs npm run X, atl next X runs next build X) matters only through user rules.
