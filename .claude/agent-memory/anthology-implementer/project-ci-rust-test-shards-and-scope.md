ci/jobs/rust-scope.sh (rules ci/scope-rules.tsv, weights ci/test-weights.tsv, graph ci/jobs/rust-graph.mjs, node plus cargo metadata --no-deps) maps changed files to crates plus every dependent (dev deps count; the closure for atl and fuzz ignores them), the golden surfaces of those crates, atl, atl-macos, fuzz and macOS, and prints linux_matrix and macos_matrix for ci.yml. Pushes, workflow_dispatch, the full-ci label, a [full-ci] anywhere in a commit message (even in prose: it fired on its own PR) and ci/jobs/rust-*, ci.yml, rust-test.sh, toolchain, root Cargo non-version changes run everything. A path no rule places also runs everything; repo-tests/tests/ci_scope.rs checks every tracked path, rule, weight and crate. The golden replay is one test per surface, golden_replay::<surface> (crates/difftest/tests/golden.rs); the rest shards skip them with --skip golden_replay::. Gates rust-test-linux and rust-test-macos stay the required checks (rust-gate.sh JOB SCOPE RUN SHARDS). Trap: cargo test -p X does not build the anthology binary that memory, runtime and dev tests run (testkit run_bin); rust-test-linux.sh and rust-test-macos.sh build anthology-cli first for those crates (needs_binary list, pinned by rust_test_jobs.rs). Trap: the old-tool name check (atl_rename.rs) refuses the legacy trim surface name unless the line says legacy. Cache: ci/jobs/rust-cache.sh binds the anthology-cargo, anthology-rustup-* and anthology-sccache volumes to runner folders that actions/cache restores (save only on push), with ANTHOLOGY_SCCACHE=1 because rust-test.sh turns sccache off in CI. A PR can only restore caches saved on its base branch, so the first run after merge to build seeds them. Measured 2026-11-27 with a warm cache: a Linux shard compiles in 19-30 s and every sampled shard hit; a macOS shard (Swatinem/rust-cache) hit and still took 13 min because it runs repo-tests (shims tests ~100 s each, two binaries). The macOS pool queued 20-45 min while other runs held it, so any PR that needs macOS waits on that pool. Repository jobs (PR ci/scope-always-on-jobs): the rust-scope output jobs is a ,a,b, list; ci.yml gates 11 jobs with needs: rust-scope and if: contains(needs.rust-scope.outputs.jobs, ,NAME,). Rows: job:NAME effects on paths, and crate:NAME rows (job runs when that crate or a dependency changed, computed from crates/* paths only so the pkg:repo-tests of a docs edit does not count; no crate:repo-tests row, or any repo-tests test edit would run the job). gitleaks, deny and shellcheck are never scoped (security, guard shell scripts). ci_scope.rs pins ALL_JOBS against ci.yml, so a typo in an if cannot skip a job unseen. Review ruling: macOS keeps repo-tests whenever it runs at all, because its tests run hooks (superpowers session-start, no-attribution, shims) and read the mods truth table under macOS bash 3.2; those paths have macos rules. Repo-tests tests that run scripts/*.sh under bash also meet macOS, but scripts/ has no macos rule (older gap, not closed). Traps: a rules row naming the word for the old interpreter fails cutover_docs, so use port/*-test-* globs; a comment line starting with the tool name followed by a word is read by shellcheck as a directive (SC1073); a skipped matrix job (plugin-validate) shows as one unexpanded check, which a required check on a target name would never see. shims-distros step (c) validates both plugins again, same as plugin-validate, so any change in those plugins runs it. Why: a PR round was 17+ min and the shared runner pool queues, so fewer jobs per PR finish sooner.
