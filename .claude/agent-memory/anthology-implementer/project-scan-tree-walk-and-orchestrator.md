crates/anthology-scan/src/tree.rs: DiskTree walks breadth first with names sorted, so shallow files come first when max_files cuts the walk. read() opens only regular-file entries, checks lstat then fstat (same dev and inode), and adds up bytes read; past max_bytes every read returns ErrorKind::QuotaExceeded and partial() turns true. skipped() holds raw paths with a trailing slash and errors() quote names with the Debug format; the report must escape both. Git modes passed to open are octal values (0o120000 symlink, 0o160000 submodule), as fetch reads them from ls-files; the decimal digits 120000 are not a symlink (lead ruling, pinned by a test). A top-level .git folder gives only .git/config and non-sample .git/hooks files in path mode and nothing when modes are given. files::classify_with order: binary (magic or NUL outside UTF-16), Agent, a #! first line (Code, language from the interpreter, unknown is Sh), then name and extension. files::magic names are ELF, Mach-O, PE, WebAssembly, zip, gzip, xz, 7z; payload.rs uses them and files::line_of is the one line counter. src/scan.rs: Hooks is a table of function pointers (REAL = the rule modules); tests swap in stubs so the orchestrator is tested without the rule tasks. raise_twins (hidden::raise_homoglyph_twins) is called once with every entry path after the per-file rules. Chain order: yara hits are mapped (high MEDIUM, medium LOW, low INFO) and raised one level in reached files, then twins are raised, then each Surface is classified and its finding emitted (files_run resolves against Surface.dir, the root as an empty string), then one finding per (rule, path) is kept: highest severity, first line on a tie, counts summed. Why: later tasks (rules, report, CLI) rely on these names and on this error and partial behavior.
