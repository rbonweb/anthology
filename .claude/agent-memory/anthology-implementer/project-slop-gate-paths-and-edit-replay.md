In crates/anthology-slop/src/paths.rs, Path::starts_with of an empty path or "/" is true for every path, so exempt() ignores a config_dir with no normal component (an unset or empty CLAUDE_CONFIG_DIR would otherwise switch the gate off for every file). Only the part below the repo root is read for EXEMPT_DIRS, which is what keeps a worktree under .claude/worktrees/id gated. exempt() does not normalise ".." lexically: .claude/../docs/a.md reads as exempt, so the CLI hands it an absolute, normalised path. Folder names match in ASCII case-insensitive form (macOS Vendor/). Story and test files are exempt by file name: a dotted part stories, test or spec that is neither the first nor the last part (Button.stories.tsx, a.test.md; not test.md); the folders __tests__ and stories are in EXEMPT_DIRS. A submodule under an exempt folder is exempt: when the nearest root has a .git FILE whose gitdir line points into .git/modules (the last of modules or worktrees decides), exempt() also reads the part below the next repo up, and so on. A .git FOLDER (a plain nested clone, say ~/build/proj under a dotfiles repo) and a worktree file (.git/worktrees) do not walk up: walking up for them would switch the gate off for a worktree under .claude/worktrees or for any repo that sits below a build or dist folder. shown() escapes control characters because the path is printed into messages the agent reads. In edit.rs, added_lines treats blank lines as neither new nor merging, merges only consecutive new lines, and compares lines with the line ending removed; an Edit uses it on its old and new text (spans are the lines of new that are not lines of old, shifted to each place it lands), so a line the Edit keeps is not new; line_spans drops a range that starts at 0, ends before it starts or starts past the last line. report.rs hook_message takes the Kind (tool, shown, kind, findings): Markdown and Html show the HTML comment waiver, Jsx the {/* */} one, Css the /* */ one, and only Markdown and Html mention a code span. rules_table() ends every line with a newline, so the caller prints it without adding one. Why: these decisions are not in the plan text and the CLI (Task 7) and the after-work check (Task 10) build on them. Test fixtures: the repo-tests docs.rs test test_no_real_home_paths scans every public file for home paths and only accepts the placeholder names listed in PLACEHOLDER_NAMES (user, someone, tester, example and so on), so a fake home folder in a test must use one of those names. The failure shows only in the CI shards, not in a per-crate run.
