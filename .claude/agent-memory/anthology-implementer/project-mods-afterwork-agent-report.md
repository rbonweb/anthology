plugins/anthology/hooks/mods/afterwork.ts checks writer reports on agent.report. AgentReportInput carries agentId, parentAgentId, subagentType, provider, status, text and no path, so agentFolder() uses $.agent.list() cwd for the agentId, skipped when its realpath ($.fs.stat resolve) equals the session cwd or root. Why: the lead cannot guess a worktree from report text, and the session folder holds the lead own changes. dirtyFiles (one git status) and slopGaps (git rev-parse HEAD in the lead cwd, then anthology slop check --root <folder> --since <sha> through runAnthology) both start from it and run together under Promise.all. A block comes only from real gaps (commit, test evidence, attribution, uncommitted files, slop tells, slop waivers); the project map and leftovers are reminders that ride in a block and never raise one, because a review found good reports got a block every time. The git pathspec is :(top) plus :(top,exclude).claude/agent-memory so a subfolder cwd still sees the whole tree and agent notes are ignored (checked by hand in a scratch repo).
Slop part: the sha must be 40 or 64 hex digits (an option-looking HEAD never reaches the binary), only exit 0 and 1 count, lines are matched against the CLI line formats and control characters become spaces because the excerpts are agent file text. In afterwork.test.ts the engine routes git rev-parse and the binary to World.calls and World.slop, so the git status runs array keeps counting status calls only; World.slop set means the fake install (HOME, lock, binary and .sha256 stats) exists.
Map claims: when MAP_ABSENT matches anywhere in the report (no map, map missing, a quoted Read error naming reference-project-map.md, ENOENT), only $.fs.exists decides, walking up from the agent cwd to the first folder holding .git. Never test the leftover text against MAP_DEALT_WITH in that case: a quoted error names the project map itself, which a review showed would hide the claim from the file check.
Tests: sh ci/jobs/mods.sh runs validate and plugin test in a node container (tsc mode is the dev type check); a run takes about 1 to 4 min, mostly npm ci; wait with timeout 170. In plugin tests a second on() for the same event does not reliably override the first, so give the world helper function or object fields (files: { includes }) instead of re-registering. The test of keeping core review and warning passed even against a hook returning only text, so it cannot prove the spread.
