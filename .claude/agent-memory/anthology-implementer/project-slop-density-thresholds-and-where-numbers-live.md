crates/anthology-slop/src/rules/density.rs holds the limits: em dashes need 150 new words and fire above 1 per 80; lists of three need 300 new words and fire above 1 per 150. A spaced en dash between range ends (digits, times, day or month names, am or pm) is not counted. The same numbers are printed in crates/anthology-slop/src/rules/mod.rs (summary strings), crates/anthology-slop/src/report.rs (the rules table test pin) and docs/slop-gate.md (rules table). Change all four together or the docs and the table drift. Tests in density.rs pad their docs with filler words to pass the minimums: a negative test with fewer words than the minimum proves nothing, so pad it. Why: the review fix touched only density.rs and left the summary text saying 1 per 120.

Structure is not counted (review 2 I4, review 3 I7): density.rs reads the line of each dash once (DashLine, linear). Skipped: every dash in an ATX heading or a table row; every dash inside a [...] pair on the line; the first two dashes from the one after a label (bold, linked bold, underscore, masked code, optional task-list box and list marker, optional colon and short value; a bare **Term** — definition line counts too); the one dash after a leading date, version or clock time (13:55, 9:05 am, 13:55 UTC), with or without a list marker. Every dash of a line is read, new or not, so the skips fall on the first ones. The mask view (markdown.rs LEAD_TERM) also records bold-lead dashes in dash_skip; density.rs repeats the check so plain views behave the same. Lists of three use [^\S\r\n] between words, so a list never crosses a line break. A match is not a list when the next word starts an object (the, a, an, your, their, its, this, our, his, her, my, it, them) or the word before it is when, if, where, as, once or unless. Do not add is/are/was to those lists: "is fast, secure and scalable" is the typical tell. plugins/anthology/agents/scout.md and marketer.md must stay clean: a unit test reads both with include_str.
