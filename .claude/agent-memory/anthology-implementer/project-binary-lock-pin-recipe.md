scripts/dev.sh runs in a container that mounts only the worktree, so checksums.txt and the release JSON must be copied under target/ (gitignored), not left in /tmp. Order: lock write, lock check, lock check-fresh, hand-edit atl.lock, version-bump check, then the lock tests. Unset ANTHOLOGY_BUILD_HOST (env -u) so nothing goes to a remote build server.
Lock write usage: scripts/dev.sh lock write --tag anthology-bin--v<ver> --checksums <file under target/> --release-json <file under target/>. Download checksums with gh release download <tag> -p checksums.txt --dir target/lock-in/bin.
Run the tests in one call: scripts/rust-test.sh run sh -c 'cargo test -p repo-tests --test atl_lock --test shims --test cutover_hooks && cargo test -p repo-tests --test ci -- lock_fresh'. Why: cargo test takes only one positional name filter, and name filters after -- match test names, not test file names. There is no lock_fresh test file: the tests are lock_check_tests::lock_fresh_* in crates/repo-tests/tests/ci.rs, so they need their own filtered run.
Why background: each dev.sh or rust-test.sh run installs apt packages again, so on a saturated Docker VM one call took 5 to 40 minutes. On an idle VM (2026-11-27) lock write, check-fresh and the test run each finished in under 3 minutes. Run them in the background and one at a time; a second call fights over the same target volume.
Version gate: scripts/dev.sh version-bump origin/build HEAD (needs a commit; it reads commits, not the working tree) compares plugin.json against the latest release tag, and a bump already on the base counts (ADR-036). A lock PR needs no bump when build already holds a version above the latest tag (2026-11-27: anthology 0.5.7 and guardrails 0.2.16 over 0.5.6 and 0.2.15). Older runs needed a bump because the gate compared against the base branch version; run the check instead of assuming. The anthology dependency range on guardrails (plugin.json) is a floor raised only when anthology needs a guardrails feature.
The release JSON needs name, digest and url per asset (lock write fails with "the release listing has no single asset <url>" without url): write it with the Write tool from gh release view --json assets.
atl.lock has no dev.sh subcommand and no other tool: lock handles only anthology.lock. Edit plugins/anthology/atl.lock by hand from the atl release checksums.txt, after checking each hash equals the digest in gh release view --json assets (a placeholder lock holds all-zero hashes and the new version already); crates/repo-tests/tests/atl_lock.rs checks it.
check-fresh compares the shipped set (crates the CLI is built from, including anthology-core Cargo.toml and src) between the lock tag and HEAD. Merging build after a core change makes it fail, so pin from the newest build and rerun check-fresh after every merge of build.
Waiting without noise: gh run watch prints the whole job tree every 3 seconds, so use timeout 170 gh run watch <id> --exit-status --compact --interval 60. dev.sh calls move to the background after the tool timeout and print only at the end; block on them with timeout 170 tail -f <task output file> in repeated calls. Do not run dev.sh --help: it starts the container build.
