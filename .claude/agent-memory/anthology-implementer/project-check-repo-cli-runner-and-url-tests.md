crates/anthology-cli/src/cmd/check_repo.rs: RealRunner starts each child with env_clear, stdin null and anthology_core::sys::new_session (setsid in pre_exec), and kills the group with sys::kill_group at the deadline. Why there: the workspace allows unsafe only in anthology-core sys.rs (GC-18) and anthology-cli forbids it, so any new libc call (new_session, kill_group, exited, announce_group, catch_termination) goes into sys.rs with a SAFETY comment.
Cleanup: a Guard lists the running child groups and the folders this run made (quarantine, its .<name>.template sibling, scratch). sys::catch_termination turns SIGINT, SIGTERM and SIGHUP into bytes on a self-pipe; a thread calls Guard::shutdown (kill groups, remove folders, refuse new children) and exits 128 plus the signal. Each child also gets a watchdog: /bin/sh in its own session reading a pipe that only this process writes to; a done line means stand down, a closed pipe with no line (SIGKILL, crash) means kill the group and rm -rf the registered folders. macOS has no PDEATHSIG, so the pipe does it. Only a folder that did not exist before the run is registered, because the watchdog runs rm -rf on the list, and every path is made absolute because the watchdog runs in /.
The watchdog starts BEFORE the child and the child writes its own pid to the watchdog pipe in pre_exec (sys::announce_group), so the group is known from the first moment the child exists. The old order (fork the child, then start the watchdog, then tell it the group) left a window in which a SIGKILL of the CLI left the child unwatched and the scratch folder behind; on a loaded host it failed a_killed_cli_leaves_no_tool_and_no_scratch_folder 2 times in 30 runs. A run that dies before any child exists still has its folders removed (end of pipe before any group line).
The main thread must never beat the signal thread to the exit: shutdown kills git, git exits, the fetch reports a failure and the main thread would exit 3 ahead of exit(143) (seen on the GitHub Linux runners, never on Zorin). Guard::defer_to_signal parks the main thread forever when the guard is down; the down flag is set under the lock shutdown holds while it kills and removes, so the main thread cannot get past the lock before cleanup is done. It is called after a child ends (RealRunner::run), before the quarantine is removed (execute) and before run_with returns. Unit tests prove this (the runner must not return after shutdown); the 5x10 interrupt stress test in tests/check_repo.rs cannot reproduce the race on Zorin.
Children are reaped last: sys::exited (waitid with WNOWAIT) sees an ended child without reaping it, so the zombie keeps the pid and the group id while the group is killed, and Registered::reap takes the child out of the guard (the watchdog stands down) before child.wait(). Child::try_wait reaps at once and would free the id for a stranger before a late group kill.
--into with a .. is refused (CLI and fetch): a path through a missing folder looked new while naming an existing one, and an interrupt would have removed it.
Flaky-test method that worked: a loop script (a throwaway file, deleted before the commit) that runs the whole integration file twice at a time on Zorin 15 times; a single-test stress inside one process did not reproduce the kill-window race, but the full-file runs did.
Tests: a hung fake ssh or tool writing a heartbeat file in a loop; the file stops growing once the group is dead. Mutation check: removing the done line semantics made the watchdog delete the quarantine after every git step.
URL mode is tested over ssh://example.invalid/<abs repo path> with a stand-in ssh script first on PATH that runs git upload-pack locally; fetch passes PATH through (absolute entries only). An https test server cannot serve a fetch: fetch clears the environment, so git cannot be given the test CA, and the server is only good for the failed-fetch case (certificate error, exit 3, quarantine removed).
In the Rust container nothing reaps orphans, so a killed grandchild stays a zombie and kill -0 still succeeds. Prove a group kill by a pipe reaching EOF (the grandchild holds the write end) or by a file that stops growing.
The scratch folder of the tools is hand-made under TMPDIR (mode 0700, removed on drop) because tempfile is a dev-dependency everywhere; the run refuses when TMPDIR is inside the target.
Tests that write a bidi character into a name see it as an uppercase escape: \u{202E}, not \u{202e}. A libtest filter after -- applies to every test target of the run, so integration tests need their own run.
