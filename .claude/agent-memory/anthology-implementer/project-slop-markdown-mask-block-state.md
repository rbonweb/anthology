crates/anthology-slop/src/mask/markdown.rs reads lines with a small state (Flow): no_paragraph (indented code needs it), in_list (fences may be indented any amount and indented lines are prose), and the open indented-code span. Indented code is masked from its first line to the end of its last, not the blank lines after it. A doc that starts with an indented line counts as after a blank line (CommonMark). MDX import and export statements run over lines by counting brackets (strings, line comments and template literals skipped); only a first line that looks like JavaScript (ESM_START) starts a multi-line statement, so prose that starts with the word import masks one line. Tags that start their line are scanned for the first > outside quoted attribute values and braces, on the doc not the buffer, because a lone > line is masked as a blockquote first. Quotes: markdown.rs has its own mask_quotes (wraps across lines until a blank line, 300 chars, curly single marks) because mask/common.rs is shared with html.rs and jsx.rs and has its own owner. Why it matters: every scan is forward-only (comment and pre closers are memoised once none is left, a tag scan that gives up is not retried inside the span it covered), and the hook blocks on its 60 s timeout. The test masking_stays_linear_on_hostile_input pins this; with the pre-closer memo removed it does not fail, it runs for minutes (about 174k openers rescanning 1 MiB), so stop that container by id. Docker runs were 5 to 10 times slower than usual with load above 150 on the host: chunk the waits.
