rules/autorun.rs hooks used by scan.rs: surfaces (per file), npm_scripts, entry_findings(paths) (autorun.git-hooks HIGH for every .git/hooks entry, root or nested, symlinks and unreadable included), and raise_gitattributes_filters(file, findings), which is also offered every git hook file (is_git_hook) and first calls lower_hook_stubs: a stock pre-commit, git-lfs (echo and printf forms) or lefthook stub becomes LOW, an edited one stays HIGH. Max severity wins in scan::merge, so a stub can only be lowered before merge, never by a second finding. Every setup.py is an Install surface (autorun.setup-py), so a clean one shows MEDIUM. Rules read lossy bytes when text is None. A package.json, tasks.json, devcontainer, settings or code-workspace file that does not parse gives HIGH autorun.unparsed and a raw-text scan (keyed values plus shape regexes on raw lines). Cargo wrapper or runner: a path is HIGH, a bare name (sccache, probe-rs) MEDIUM. VS Code program settings: path in the repo HIGH, outside or under node_modules MEDIUM, bare name nothing. tomlish Kv.table is an Rc<str>. Hostile-input traps found by tests: recursion on dependsOn chains and nested objects overflowed the stack (depth caps), per-entry clones or lowercase of a huge section header went quadratic (share an Rc, work out the section name once), line continuations joined by format! went quadratic (push_str), per-match line_at over a 2 MB file went quadratic (count lines in one pass). Timing tests use a 15 s bound because the debug build on the shared host is slow under load. Why: the scan reads untrusted repos, so one 2 MB file must never hang or abort it.
