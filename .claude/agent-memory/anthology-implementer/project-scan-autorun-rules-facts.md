rules/autorun.rs hooks used by scan.rs: surfaces (per file), npm_scripts, entry_findings(paths) (autorun.git-hooks HIGH for every .git/hooks entry, root or nested, symlinks and unreadable included; it also lowers a HIGH autorun.vscode-program finding to LOW when its target is not an entry or folder of the tree, because scan.rs passes it every finding made so far), and raise_gitattributes_filters(file, findings), which is also offered every git hook file (is_git_hook) and first calls lower_hook_stubs: a stock pre-commit (absolute python, default config), git-lfs, lefthook (heuristic, no inline interpreter code), husky 4 (hook, husky.sh, husky.local.sh) or simple-git-hooks (prelude plus one known lint tool) stub becomes LOW, an edited one stays HIGH. Max severity wins in scan::merge, so a stub can only be lowered before merge, never by a second finding. Every name is matched in ASCII lower case (dispatch uses a lower-cased copy of the path; path_is, dir_above, git_hook_name fold case). Files under .husky/_ are skipped only when they are the stock husky 9 files; any other file there is a husky hook surface. Every setup.py is an Install surface, so a clean one shows MEDIUM. Rules read lossy bytes when text is None. A package.json, tasks.json, devcontainer, settings or code-workspace file that does not parse gives HIGH autorun.unparsed and a raw-text scan. Cargo wrapper or runner: a path is HIGH, a bare name MEDIUM. VS Code program settings are an explicit key list (not a prefix rule); a repo path is HIGH, outside the repo, node_modules or an unresolvable variable MEDIUM, bare name nothing. Task options: shell.executable and args (task, platform block, file level) prefix the command so shape::files_run sees an in-repo shell; env keys that run code give autorun.vscode-task-env (own table in autorun.rs, not shared with agent.rs). shape::files_run treats a relative word with a folder part (./tools/sh) as a repo file even when named like an interpreter. shape::severity: Build plus FetchExec is HIGH, DecodeExec and RunsData stay CRITICAL. ini_entries joins backslash continuations for git config and .gitmodules only. tomlish Kv.table is an Rc<str>. Hostile-input traps found by tests: recursion on dependsOn chains and nested objects overflowed the stack (depth caps), per-entry clones or lowercase of a huge section header went quadratic (share an Rc, work out the section name once), line continuations joined by format! went quadratic (push_str), per-match line_at over a 2 MB file went quadratic (count lines in one pass). Timing tests compare a 10x input or a huge name against a small one on the same host (40x bound, 20 ms floor), never a fixed number of seconds, so a busy host does not flake them. Why: the scan reads untrusted repos, so one 2 MB file must never hang or abort it.
