## 0. Protocol

### 0.1 Rules for every lane

1. **No live switch before CO2.**
   - Until cutover, nothing a user or CI already runs changes behaviour: `hooks.json`, `skills/*/SKILL.md`, `bin/*`, `scripts/*.sh`, and workflow steps that run Python.
   - Final versions are written under `port/staging/<same relative path>`, tested there, and moved into place by CO2.
   - Additive repo changes (new crates, jobs, workflows, Dockerfiles) land directly. F1 creates all of them up front (§0.2).
2. **Python source is read-only**, except:
   - the oracle drivers in `port/difftest/oracle/`;
   - the extractors in `port/extract/`;
   - Python meta-test edits that an additive change forces. These are made **only by the controller**, in a plumbing PR (§0.2).
3. **Definition of Done (DoD) for a task:**
   - `scripts/rust-test.sh` is green (`fmt --check`, clippy `-D warnings`, `cargo test --workspace --locked` in the rust image), and so are CI `rust-test-macos` and `shims-distros` where the task touches shims;
   - `cargo deny check` is green;
   - `scripts/difftest.sh --surface <the task's surfaces> --gen 10000` gives **0 unexplained diffs** on Linux, and on macOS for CLI surfaces;
   - `ci/jobs/ledger.sh --files <the task's Python test files> --task <ID>` is green (it runs `ledger check --fresh`; a bare `ledger check` without `--fresh`/`--no-fresh` exits 2);
   - spec review and code-quality review pass (`stream-protocol.md`, at most 3 fix rounds).
4. **Counts come from the ledger (N-I3).** Every per-file count in this plan is an informational snapshot at `rust@1e00f832`. The acceptance criterion is always "every id of that file in `port/python-test-ids.txt`", regenerated on each `build`→`rust` merge.
5. **Tests keep the Python method name.** Table rows live in `crates/<crate>/tests/data/<python_module>.jsonl`, tagged `"py": "<python id>"`. A row may be `ported` only if the Rust test drives the **same branch**, through a GC-19 seam where Python patched something (rule 5 above).
6. **Commits** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Lanes do not bump plugin versions; CO2 does.
7. **Sizes** count Rust lines, implementation plus tests: S < 800, M 800–2,000, L 2,000–4,000, XL > 4,000.

### 0.2 Merge discipline (I-5)

1. **F1 pre-declares everything shared.** Lanes then **never edit** these files:

   | Shared item | What F1 puts there |
   |---|---|
   | root `Cargo.toml` `[workspace.dependencies]` | every crate in D§11.2, exact versions |
   | every crate's `Cargo.toml` | all the dependencies that crate will need |
   | `Cargo.lock` | committed |
   | every `lib.rs`, and `anthology-cli/src/{main.rs,cmd/mod.rs}` and `anthology-dev/src/main.rs` | every module file named in any task's **Files**, as an empty `mod` stub; every subcommand registered (§1.3) |
   | `crates/difftest/src/surfaces/mod.rs` | every surface name registered (§1.4) |
   | `fuzz/Cargo.toml` and its lock | every fuzz target as a stub |
   | `ci.yml` | **real** `rust-lint`, `rust-test-linux`, `rust-test-macos` and `deny` jobs; a new `.github/workflows/fuzz.yml`; placeholders (calling `ci/jobs/<job>.sh`) **only** for jobs a named lane fills (§4 F1 lists job → owner). **Existing live jobs, including `rtk-test`, stay untouched until CO2** (N-I5) |
   | Cargo `[features]` (m-R10) | `anthology-core/test-faults`, `anthology-guard/panic-on-marker`, `anthology-guard/test-watchdog`, and `anthology-cli` features forwarding all three |
   | `crates/repo-tests/src/repo.rs` (m-R11) | a minimal repo-root and file helper, used by F1, BS1 and RL1 before MT1 extends it |
   | `.gitignore` | the replay entries |
   | `ci/images/*.Dockerfile` | the new pinned images |

   A job script lives in `ci/jobs/<job>.sh`, so a lane edits its own script, never `ci.yml`.

   If a lane needs a shared change, the controller makes it in a small **plumbing PR** that merges first.
2. **Shared ledgers are split:**
   - `port/ledger/<python_module>.tsv`;
   - `port/difftest/divergences/<surface>.toml`;
   - testkit helpers in `crates/anthology-testkit/src/<lane>.rs`.
3. **Merges are serial.** The controller merges one lane at a time into `rust` (a merge queue). Before its own merge, every other open lane merges the new `rust` in and re-runs its DoD. Only the controller regenerates `Cargo.lock`, with `cargo update -w --offline`.
4. **Python meta-test edits** caused by additive changes are made by the controller in the plumbing PRs. MT1 **merges last** in wave 1, so its Rust ports include them.
   - **After MT1 has merged (m-R12),** any such edit updates the Python test **and** its Rust port in the same plumbing PR.
   - This includes **RG1's edits to the live `scripts/rtk-test.sh` and `rtk-net-test.sh`**, which `test_rtk_layout` asserts. They are the one stated exception to §0.1.1, and they go through a plumbing PR.
5. **Single owners of contested files:**
   - **RL1** owns `port/staging/scripts/release.sh`.
   - **DV2** owns `port/staging/scripts/sync-rtk.sh`.
   - **DV1** owns `anthology-dev vendor set-rtk-upstream`.
   - **DV4** owns the rtk_trim `--lock-guard` allowlist.
   - **BS1** owns every file under `port/staging/plugins/*/{hooks,bin}/`.
   - **CO2** owns every file move out of `port/staging`.
   - **`repo-tests` (m-R11):**
     - F1 owns `src/repo.rs` (minimal), `tests/toolchain.rs`, `tests/no_serde_json.rs` and `tests/no_replay_tracked.rs`;
     - RL1 owns `tests/anthology_lock.rs`;
     - BS1 owns `tests/shims.rs`;
     - CO2 owns `tests/cutover_*.rs`;
     - MT1 owns every other test, and extends `src/repo.rs`.

### GC-17 Bootstrap constants

- **Lock.** `<plugin root>/anthology.lock`, in the D§8.2 layout exactly.
  - `version` matches `^[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.]+)?$`
  - `tag` = `anthology-bin--v` + version
  - `repo` matches `^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$`, with no `.` or `..` parts
  - hashes match `^[0-9a-f]{64}$`
- **Asset** `anthology-<target>.tar.gz` (`anthology`, `LICENSE`). **URL** `https://github.com/<repo>/releases/download/<tag>/anthology-<target>.tar.gz`.
- **CLI:** `bootstrap.sh <session|guard|wrapper> --plugin <anthology|guardrails> [--quiet] [--budget S]`.
  - `session` is never rate-limited and never writes `.attempt`. It honours the strike cap, except for one fresh attempt per hour through `.session-retry` (A28, m2-6).
  - `guard` and `wrapper` are rate-limited and honour the cap.
- **Step order:** platform, lock, `mkdir -p <ah>/bin` (refuse a symlink), current?, cap and rate limit, archive, hash, extract, **`--version` probe under the watchdog; a failure moves the staged binary to `.broken-…` (a strike)**, then place (`.bin-sha256` before `.sha256`).
- **Placement failure:** `cannot write the install folder` only if `test -w <ah>/bin` fails. Otherwise retry the placement once, then `install interrupted by a parallel change` (m2-2).
- **Sources, in order:**
  1. seed `<ah>/bin/anthology-<target>.tar.gz`. If its hash does not match it is skipped and kept, and the reason is named only if everything else fails;
  2. curl `-fsSL --proto '=https' --proto-redir '=https' --connect-timeout 10 --max-time $B --max-filesize 67108864 -A anthology-bootstrap`;
  3. GNU wget `--https-only -q -T 10 -U anthology-bootstrap`, under the watchdog;
  4. BusyBox wget `-q -T 10`, under the watchdog;
  5. `NODE_USE_ENV_PROXY=1 node -e "$NODE_GET"` (a fixed constant with a byte-equality test; https-only, ≤ 5 redirects, 64 MiB, own timeout), under the watchdog. It honours `HTTPS_PROXY` only on node ≥ 24, and `node` may not be on `PATH` for native installs (documented).
- **Watchdog** (D§8.4 form): stdio to `/dev/null`, and the `sleep` is killed by a `TERM` trap, so a fast download returns at once (m-R4).
- **Budgets:** `BOOTSTRAP_BUDGET` 20 s (`session`, `guard`, `wrapper`); setup uses 60 s.
- **Rate limit.** 60 s through `<ah>/bin/.attempt`.
  - A stale stamp is retired atomically (`mv -f .attempt .attempt.stale.$$`), then the new one is created with `( set -C; : > .attempt )`.
  - A failed create is `rate-limited` only if `.attempt` exists **and is newer than 60 s**; otherwise it is `cannot write the install folder` (m2-3).
  - A narrow race may still start two downloads, which is harmless (m2-4).
- **Integrity:**
  - "installed" = real directory + regular, **non-empty** (`test -s`), executable binary + non-empty `.sha256`;
  - "current" = installed + `.sha256` == the lock hash + `.bin-sha256` == the binary's sha256;
  - install requires the `--version` probe: exit 0 and exact output `anthology <version> (<target>)`.
- **Allow token (N2-I1):** exactly `anthology-guard:allow:v1` followed by one `\n`, written to stderr by `anthology guard hook --shim` on allow and never otherwise.
- **Hot-path classification:** `err=$("$bin" guard hook --shim 2>&1 >/dev/null); rc=$?`.
  - `rc=0` **and** `$err` = `anthology-guard:allow:v1` (`$(…)` strips the newline) → allow.
  - `rc=2` with `$err` starting `Blocked by anthology-guardrails (` → pass the block through.
  - **Everything else** → quarantine. This includes `rc=0` with empty stderr (a NUL-filled, whitespace-only or script file run by the shell) and `rc=0` with any other stderr.
- **Fail-closed invariant (m2-12):** `guard.sh` has exactly two `exit 0` sites, the token allow and the read-only allowlist. Every other path ends in a block. `present` and `installed` both lead to running the binary.
- **Quarantine.** `mv <version> .broken-<version>-<epoch>-<pid>`.
  - Strikes are counted by the `<epoch>` in the name: 3 within 86,400 s. Pruning uses the same epoch, older than 24 h.
  - A failed `mv` gives the "not set aside" message only if `<version>` still exists. Otherwise (a parallel call won) it gives the "set aside" message (m2-2).
  - The third quarantine uses the three-strikes message.
- **Read-only allowlist:** `Read Grep Glob LS NotebookRead WebFetch WebSearch TodoWrite TaskCreate TaskUpdate TaskGet TaskList TaskOutput TaskStop Task Agent Skill ToolSearch AskUserQuestion EnterPlanMode ExitPlanMode BashOutput KillShell`.
- **Prune:** version directories after 30 days unused; `.tmp-*` and `.broken-*` after 24 h (by name epoch for `.broken-*`).

### GC-18 Engineering rules

- **Toolchain** `1.100.0`, edition 2024. Only the **channel** must equal rtk's (m-17).
